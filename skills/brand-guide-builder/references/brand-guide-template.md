# Brand guide — section structure

This is a **content checklist**, not a visual template — it defines what
goes in the final guide and in what order, so nothing gets dropped. The
actual look (colors, layout, type, tone) should come from the user's own
brand, not from any fixed house style. When building the published HTML
page, use the frontend-design skill for craft (spacing, hierarchy, real
typographic choices) but let the content drive the aesthetic.

1. **Cover** — brand name, tagline (if given), year/date.
2. **Foundations** — personality traits, voice words, target audience, and
   a short "about" paragraph synthesized from Step 1's answers (don't just
   list the raw words — write 1-2 sentences that actually sound like the
   brand, using its own voice words as a style guide for how to write it).
3. **Color palette** — every color with name, hex, and role (Hero / Accent
   / Light Neutral / Dark Neutral). Include a compact accessibility summary
   (the ≥2 AA-approved combinations from Step 2, stated plainly: "use X on
   Y for body text" style guidance, not just a raw ratio table — though the
   full table can live in an appendix or expandable section).
4. **Typography** — heading font, body font, accent font (if set), each
   shown as an actual type specimen (real sample text rendered in that
   font at a few sizes), plus the hierarchy (H1–H6, Body L/M/S) if defined.
5. **Buttons & links** — rendered examples of the actual button style
   (fill, shape, color) in default and hover states, plus the underlying
   rule written out in words ("primary buttons: filled, [hero color]
   background, [shape] corners").
6. **Logo usage** — the logo itself (if uploaded) in its variants, clear
   space / minimum size notes, and the favicon if applicable. If no logo
   was uploaded, note this explicitly as an open item rather than
   inventing a logo.
7. **Quick-reference summary** — a single condensed page/section repeating
   just the hex codes, font names, and button rule in the smallest
   possible form, for someone skimming rather than reading the full guide.

Keep the whole document scannable — short paragraphs, real visual
examples wherever something can be shown rather than described (a color
swatch beats a hex code alone, a rendered button beats a text
description of one).
